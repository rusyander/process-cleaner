# Windows Process Cleaner

🇷🇺 Русский · [🇬🇧 English](README.en.md)

Обслуживание Windows в одном окне: **очистка диска**, **завершение забытых процессов**,
**освобождение оперативной памяти**, **обновление установленных программ**, управление
**автозапуском**, удаление программ и чистка **Docker**.

Написана на **C# + WinForms**, собирается **встроенным в Windows компилятором
`csc.exe`** (.NET Framework 4.x). **Ничего устанавливать не нужно** — ни Node.js,
ни Rust, ни Visual Studio. Результат — один самодостаточный `.exe`, который можно просто
носить в папке.

---

## Для чего эта программа

Один инструмент вместо набора сторонних «оптимизаторов»: убрать зря висящие процессы,
освободить память, вычистить накопившийся мусор с диска и поставить вышедшие обновления —
без установки чего-либо в систему, с предпросмотром перед каждым удалением, с русским и
английским интерфейсом, работой из трея и по расписанию.

## Из чего состоит окно

| Вкладка | Что делает |
|---|---|
| **Сканирование** | ищет заброшенные процессы и завершает их, чистит Standby Memory |
| **Dev Cleanup** | массово гасит dev-рантаймы и освобождает занятые dev-порты |
| **Очистка диска** | анализ и удаление мусора по категориям, опционально правила winapp2 |
| **Docker** | обзор занятого места и удаление неиспользуемого, сжатие vhdx |
| **Программы** | список установленного ПО, удаление штатным деинсталлятором |
| **Обновления** | поиск устаревших программ и их обновление через winget / Chocolatey |
| **Автозапуск** | что стартует вместе с Windows, включение и отключение |
| **Настройки** | все пороги, списки и параметры |
| **История** | что и когда было очищено |

## Что программа умеет

- **Процессы.** Находит забытые/заброшенные процессы (dev-рантаймы или — в глобальном
  режиме — любые ваши) и безопасно их завершает: сначала мягко (WM_CLOSE), потом
  принудительно. Показывает по каждому: PID, PPID, путь, аптайм, CPU, RAM, окна,
  TCP-порты, дочерние процессы, владельца.
- **Оперативная память.** Очищает Standby Memory через WinAPI (`NtSetSystemInformation`),
  без сторонних exe.
- **Dev Cleanup.** Массово завершает Node/Python/Java/Vite/Webpack/npm/pnpm/yarn и
  освобождает занятые dev-порты (3000, 5173, 8080, 4200 …).
- **Очистка диска.** Анализирует и удаляет известный мусор: dev-кэши (npm/pnpm/yarn/
  pip/gradle/cargo/go/NuGet), системный мусор (temp, Корзина, Windows Update, дампы),
  кэши браузеров и приложений (Discord/Slack/Teams/Spotify), старые логи, installer-мусор
  драйверов и `Windows.old`. По желанию подключаются **правила winapp2** — открытая база
  на тысячи программ. Сначала показывает размеры, удаляет только после подтверждения.
- **Docker.** Показывает занятое место (`docker system df`) и чистит неиспользуемое:
  остановленные контейнеры, образы, тома, кэш сборки, всё сразу.
- **Программы.** Список установленного ПО с удалением через штатный деинсталлятор.
- **Обновления.** Сканирует компьютер и показывает, у каких программ вышли новые версии,
  оценивает масштаб обновления («крупное / среднее / мелкое») и устанавливает выбранные —
  силами **winget** и **Chocolatey**, по нескольку пакетов за раз.
- **Автозапуск.** Список всех установленных программ с тоглом «в автозапуске Windows»:
  включаешь — добавляет, выключаешь — убирает (реестр `Run` + папка «Автозагрузка»).
- **Автоматизация.** Таймер автоочистки процессов (каждые 1–24 ч), автозапуск с Windows
  (через Планировщик), работа в трее, история очисток, гибкие настройки.
- **Оформление.** Тёмная/светлая тема (или по системе) + тёмный заголовок окна;
  язык интерфейса RU/EN.

## Чего программа НЕ делает (границы безопасности)

- **Не ломает Windows.** Системные процессы (SYSTEM/сервисы), компоненты из `C:\Windows`,
  критичные и защищённые процессы (оболочка, облака, драйверы, мессенджеры) в глобальном
  режиме под завершение не попадают; предохранители работают «в сторону защиты».
- **Не завершает активное по ошибке.** Кандидат в скане отбирается только при совпадении
  всех критериев сразу (мёртвый родитель + простой + нет окон/портов/детей), с
  подтверждением. Исключение — кнопки Dev Cleanup: это осознанная «кувалда» по имени.
- **Не ищет дубликаты файлов по диску** и не удаляет ничего из ваших проектов, кода,
  `DriverStore`, System32 и корней дисков. Чистятся только известные мусорные пути.
- **Не чистит диск, не удаляет программы и не обновляет их по расписанию** — только
  вручную, с предпросмотром и подтверждением. По таймеру работает лишь очистка процессов.
- **Не правит реестр при обновлении программ.** Установку выполняет сам менеджер пакетов
  (winget / Chocolatey), приложение только показывает список и передаёт ему команду.
- **Docker: удаляет только неиспользуемое** (`prune`) — запущенные контейнеры и
  используемые образы не трогает. Kubernetes не включён.

## Установка

### Что нужно

| Требование | Пояснение |
|---|---|
| Windows 10 или 11 (x64) | Windows 8.1 тоже подойдёт |
| .NET Framework 4.x | **уже есть в Windows**, ставить не надо |
| Права администратора | нужны для очистки Standby Memory |

Ни Visual Studio, ни .NET SDK, ни Node.js, ни какие-либо пакеты **не требуются** —
программа собирается компилятором `csc.exe`, который уже лежит внутри Windows.

Отдельно (по желанию, только для соответствующих вкладок):

- **winget** — для вкладки «Обновления». В Windows 11 и свежих Windows 10 он есть
  из коробки; если нет — установите «Установщик приложений» (App Installer) из
  Microsoft Store.
- **Chocolatey** — необязательный второй источник обновлений. Если он не установлен,
  вкладка просто работает через один winget.
- **Docker Desktop** — для вкладки Docker (нужен запущенный демон).

### Шаги

1. **Получите файлы.** Либо `git clone` репозитория, либо скачайте ZIP и распакуйте
   его в любую папку, например `C:\Tools\cleaner`.

2. **Если скачивали ZIP — снимите блокировку.** Windows помечает файлы из интернета, и
   сборка может отказаться работать. Правый клик по ZIP → **Свойства** → внизу галочка
   **«Разблокировать»** → OK, и только потом распаковывайте. Уже распаковали — выполните
   в PowerShell в папке проекта:

   ```powershell
   Get-ChildItem -Recurse | Unblock-File
   ```

3. **Запустите `run.bat`** двойным кликом. При первом запуске он соберёт
   `WindowsProcessCleaner.exe` и сразу откроет его. Дальше можно запускать сам `.exe`.

   Только сборка, без запуска:

   ```
   build.bat
   ```

4. **Подтвердите запрос UAC.** Программа всегда запускается от администратора — это
   нужно для очистки Standby Memory. Запрос при каждом запуске — нормально.

Всё. Устанавливать в систему ничего не нужно: `WindowsProcessCleaner.exe` —
самодостаточный файл, его можно просто носить с собой в папке.

### Если что-то не пошло

**«Windows защитила ваш компьютер» (SmartScreen).** Файл собран у вас локально и не
подписан сертификатом, поэтому Windows его не знает. Нажмите **«Подробнее»** →
**«Выполнить в любом случае»**.

**Антивирус ругается на свежесобранный `.exe`.** Это ложное срабатывание на
неподписанный файл. Добавьте папку проекта в исключения или соберите заново.

**`[ERROR] csc.exe of .NET Framework 4.x not found`.** В системе нет .NET Framework 4.x
(бывает на сильно урезанных сборках Windows). Установите .NET Framework 4.8 с сайта
Microsoft и повторите.

**`[ERROR] Build failed`.** Чаще всего программа уже запущена и держит свой `.exe`.
Закройте её (в том числе из трея — правый клик по иконке → «Выход») и соберите снова.

**Окно не появилось после запуска.** Вероятно, приложение уже работает: оно
однооконное и просто разворачивает уже открытое окно. Посмотрите в трей у часов.

**Не собирается из папки с очень длинным путём.** Перенесите проект ближе к корню
диска, например в `C:\Tools\cleaner`.

### Как удалить

1. В настройках снимите галочку **«Запускать вместе с Windows»** — задача
   `WindowsProcessCleaner` в Планировщике задач удалится.
2. Закройте программу (трей → «Выход»).
3. Удалите папку проекта и папку настроек `%APPDATA%\WindowsProcessCleaner\`.

Ничего другого в системе программа не оставляет: в реестр она себя не прописывает
и служб не создаёт.

## Возможности

### Сканирование
По каждому процессу собирается: имя, PID, PPID, путь, время работы, CPU %, RAM,
наличие окна, слушающие TCP-порты, наличие дочерних процессов, владелец.

### Критерии «заброшенности»
Процесс становится кандидатом на завершение, только если выполнены **все** условия:
1. родительский процесс завершён;
2. CPU ниже порога дольше заданного времени простоя;
3. нет пользовательских окон;
4. не слушает TCP-порты;
5. нет дочерних процессов;
6. не в белом списке и старше минимального времени жизни.

### Два режима поиска
- **Dev-режим** (по умолчанию) — только процессы из списка отслеживаемых
  (node, python, java, vite, webpack, npm, pnpm, yarn, bun, cargo, go, deno, ruby, php…).
- **Глобальный режим** (галочка «Все процессы (глобально)») — сканируются **все**
  процессы системы. Здесь действуют **усиленные предохранители**: завершаются только
  процессы **текущего пользователя**, лежащие **не в системных папках** Windows и
  **не в `Program Files`** (установленный софт, настраивается), простаивающие **≥ 30
  минут** (настраивается), не входящие в расширенный список защищённых (ядро Windows,
  оболочка, облака, мессенджеры, драйверы, лаунчеры, менеджеры паролей). Именно так
  отлавливаются осиротевшие группы, у которых родитель давно умер, а дети остались
  висеть и грузить проц/память, ничем не используясь.

### Кнопки очистки
- **Очистить выбранные** — завершить отмеченные в таблице.
- **Автоочистка всех неактивных** — завершить всех найденных кандидатов одним
  нажатием (с подтверждением и списком).
- **Выбрать все / Снять выбор** — управление галочками.
- **Очистить память** — только очистка Standby Memory без завершения процессов.

Само завершение: сначала мягко (WM_CLOSE), ожидание до 3 секунд, затем принудительно.

### Dev Cleanup
Массовое завершение по группам: всё Node / Python / Java / Vite / Webpack / npm /
pnpm / yarn·bun / Docker Compose / Go·Cargo·Deno. Плюс список процессов, занявших
популярные dev-порты (3000, 5173, 8080, 4200 …) с возможностью их завершить.

> В Dev Cleanup завершение идёт **по имени, не глядя на активность** (кроме белого
> списка) — это осознанная «кувалда».

### Очистка диска (только вручную)
Отдельная вкладка. Флоу: **Анализировать → предпросмотр с размерами → удалить
выбранное**. Автоочистки диска нет намеренно (файлы менее обратимы, чем процессы).
Чистятся только **известные мусорные пути**, никакого поиска дубликатов по диску.
Категории:
- **Dev-кэши** — npm / pnpm / yarn / pip / gradle / cargo / go / NuGet (пересоздаются).
- **Системный мусор** — `%TEMP%`, `Windows\Temp`, Корзина, кэш Windows Update,
  crash dumps, отчёты об ошибках.
- **Кэши браузеров** — Chrome / Edge / Brave / Firefox, только кэш (без паролей и куки).
- **Кэши приложений** — Discord / Slack / Teams / Spotify, только кэш.
- **Старые логи** — логи CBS/DISM, npm/yarn, отчёты об установке.
- **Старые драйверы + Windows.old** — installer-мусор NVIDIA/AMD, папка старой Windows.

Предохранители: пропускаются занятые файлы и точки повторного разбора (junction),
никогда не трогаются `DriverStore`, System32, корни дисков, код и проекты. Файлы, которые
изменялись в последние N минут, не удаляются (N настраивается, по умолчанию 10). Каждая
очистка пишется в лог `clean-ГГГГ-ММ.log` — кнопка «Лог» открывает его.

**Правила winapp2 (необязательно).** Кнопка «Правила winapp2» скачивает
[Winapp2.ini](https://github.com/MoscaDotTo/Winapp2) — открытую базу с тысячами правил
очистки для конкретных программ, и добавляет их к встроенным категориям. Из неё берутся
**только правила удаления файлов**: разделы с предупреждениями (`Warning=`) и с
исключениями (`ExcludeKey`) пропускаются целиком, а правила для реестра игнорируются —
реестр программа не чистит вообще. Результаты из winapp2 никогда не отмечаются галочкой
автоматически.

### Программы (деинсталляция)
Вкладка со списком установленных программ (имя, версия, издатель, размер). Отмечаешь
и удаляешь через приложение — запускается штатный деинсталлятор программы.

### Обновления программ
Вкладка находит устаревшие программы по всему компьютеру и обновляет их. Флоу:
**Проверить обновления → отметить нужные → Обновить выбранное**.

**Откуда берутся данные.** Опрашиваются менеджеры пакетов: **winget** (официальная база
Microsoft, десятки тысяч пакетов) и, если он установлен, **Chocolatey**. Сопоставление
установленной программы с пакетом и сравнение версий делает сам менеджер — приложение не
держит собственную базу версий, которая неизбежно отставала бы от реальности.

**Колонка «Важность»** показывает масштаб скачка версии:

| Значение | Когда |
|---|---|
| **крупное** | меняется старшая часть версии (14.1.3 → 15.1.1), поведение может измениться |
| **среднее** | новые возможности, совместимость обычно сохраняется (2.5.1 → 2.7.3) |
| **мелкое** | исправления и правки сборки (3.14.2 → 3.14.7) |
| **неизвестно** | менеджер не сообщает точную установленную версию |

Крупные обновления идут первыми в списке и подсвечиваются, чтобы их не пришлось искать
прокруткой. Для версий вида `0.x` смена второй части тоже считается крупной — по правилам
semver именно там в таких проектах происходят ломающие изменения.

> ⚠️ **«Важность» — это масштаб смены версии, а не оценка безопасности.** Ни winget, ни
> Chocolatey не отдают данные о CVE и критичности, поэтому вывести настоящую «критичность»
> из них невозможно, и приложение этого не изображает. Если нужно знать, закрывает ли
> обновление уязвимость, смотрите release notes самой программы.

**Групповое обновление.** Отмеченные пакеты передаются менеджеру не по одному, а группами
(по умолчанию 5 за команду, настраивается 1..20; 1 — строго по одному). Это экономит запуск
процесса и загрузку индекса источника на каждый пакет.

Установщики при этом всё равно работают **по очереди**, и это не ограничение приложения:
Windows Installer держит машинный мьютекс `_MSIExecute`, а Chocolatey — свой глобальный
лок, поэтому два установщика, запущенных одновременно, просто завершатся ошибкой.

**Как определяется результат.** После группы приложение заново спрашивает менеджер, что
ещё осталось устаревшим, и сверяет список. Так результат по каждому пакету получается
верным независимо от языка системы — разбирать локализованный текст вывода было бы гадание.

**Прочее на вкладке:**

- **Дубли.** Один и тот же софт может быть виден и через winget, и через Chocolatey. Такие
  строки помечаются и приглушаются, а кнопка «Все» их не отмечает — обновлять одно и то же
  двумя менеджерами не нужно. Пометка ни на что не влияет, кроме подсказки: отметить строку
  вручную всё равно можно.
- **«Не предлагать»** — добавляет выделенные пакеты в список исключений (настройки),
  и они больше не появляются при проверке.
- **«Лог»** — открывает `updates-ГГГГ-ММ.log`: что, когда, с какой версии на какую и с
  каким результатом обновлялось.
- **Ничего не отмечено заранее.** Обновление — действие пользователя, поэтому по кнопке
  «Обновить выбранное» сначала показывается список того, что будет обновлено, с версиями,
  и запрашивается подтверждение.
- Пакеты, у которых менеджер не знает установленную версию, показываются по умолчанию —
  это отключается в настройках.

> Установщик может закрыть и перезапустить обновляемую программу. Сохраните работу перед
> обновлением того, что открыто.

### Автозапуск
Вкладка со списком всех установленных программ и чекбоксом-тоглом. Галочка стоит —
программа в автозапуске Windows; поставить — добавить, снять — убрать. Читает и
пишет автозапуск из реестра (`HKCU\...\Run`, `HKLM\...\Run`) и папок «Автозагрузка»
(пользователь + общая). Оранжевым помечаются записи автозапуска, которых нет в списке
установленных программ (скрипты, ярлыки) — их тоже можно отключить. Добавление всегда
идёт в пользовательский `HKCU\...\Run`; по умолчанию, если программа не в автозапуске,
тогл выключен.

### Docker
Вкладка для очистки Docker (нужен Docker CLI + запущенный демон). Кнопки: обзор
занятого места (`docker system df`), удалить остановленные контейнеры, неиспользуемые
образы, неиспользуемые тома, очистить кэш сборки, полная очистка всего неиспользуемого.
Удаляется только **неиспользуемое** (`prune`) — запущенные контейнеры и используемые
образы не трогаются.

> ⚠️ **Важно про место на диске.** Docker Desktop хранит всё в одном растущем
> виртуальном диске WSL2 (`docker_data.vhdx`). `prune` освобождает место **внутри**
> этого диска, но сам файл на Windows **не уменьшается**. Чтобы реально вернуть место
> на диске Windows — кнопка **«Сжать диск Docker»**: она останавливает Docker
> (`wsl --shutdown`) и сжимает vhdx через `diskpart compact vdisk`, показывая размер
> до/после. Все запущенные контейнеры при этом завершаются.

Kubernetes не включён (его очистка бьёт по живому кластеру).

### Язык интерфейса
Русский / English — переключается в настройках (применяется после перезапуска).
Документация тоже двуязычная: [README.md](README.md) / [README.en.md](README.en.md).

### Таймер автоочистки
Задаёшь число часов (1..24). Каждые N часов приложение само сканирует **процессы**
(в выбранном режиме), завершает кандидатов, чистит память и пишет в историю. Очистка
диска и деинсталляция по таймеру **не выполняются** — только вручную.

### Системный трей
Иконка в трее меняет цвет: зелёная — чисто, оранжевая — есть кандидаты. Двойной
клик — открыть окно. Правый клик — меню: Сканировать, Очистить, Очистить Standby
Memory, вкл/выкл автоочистку, перезапуск от администратора, выход. Закрытие окна
сворачивает приложение в трей (продолжает работать в фоне).

### Автозапуск с Windows
Галочка в настройках. Реализован через **Планировщик задач** с наивысшими правами
(`schtasks /RL HIGHEST`), поэтому при входе в систему UAC не появляется.

### Темы оформления
Светлая / тёмная / **по системе** (по умолчанию — следует за темой Windows).
Переключается в настройках, применяется сразу, включая заголовок окна.

### Настройки (сохраняются)

- **Критерии заброшенности** — порог CPU, время простоя, минимальное время жизни,
  простой для глобального режима.
- **Автоматизация** — период автоочистки процессов (1..24 ч), включение автоочистки,
  «глобально: не трогать Program Files», автозапуск с Windows, старт свёрнутым в трей.
- **Производительность** — фоновый мониторинг CPU и его период (5..300 с, по умолчанию
  15), сброс рабочих наборов всех процессов (по умолчанию выключен — он замедляет систему).
- **Очистка диска** — «не удалять файлы свежее N минут», ведение лога очистки, список
  путей, которые не чистить.
- **Обновления программ** — показывать пакеты с неизвестной установленной версией,
  опрашивать Chocolatey, сколько пакетов передавать менеджеру за одну команду (1..20),
  список пакетов, которые не предлагать к обновлению.
- **Списки** — отслеживаемые процессы, белый список, dev-порты.
- **Оформление** — тема и язык интерфейса.

### История
После каждой очистки сохраняются дата/время, количество завершённых процессов,
объём освобождённой памяти и список процессов.

---

## Безопасно ли это?

**Режим сканирования/автоочистки — да.** Кандидат отбирается только при совпадении
**всех** критериев сразу, поэтому активный процесс (с окном, слушающий порт, грузящий
CPU или с живым родителем) под удар не попадёт. В глобальном режиме дополнительно
защищены системные процессы и процессы других пользователей. Перед завершением
всегда запрашивается подтверждение.

**Dev Cleanup — нет**, это намеренно «кувалда»: кнопки бьют по имени всё подряд
(кроме белого списка). Используй осознанно.

## Где лежат данные

Всё в одной папке — `%APPDATA%\WindowsProcessCleaner\`. Кнопка «Папка данных» в
настройках открывает её.

| Файл | Что это |
|---|---|
| `config.json` | все настройки |
| `history.json` | история очисток процессов |
| `clean-ГГГГ-ММ.log` | лог очистки диска (что удалено и сколько освобождено) |
| `updates-ГГГГ-ММ.log` | лог обновлений программ |
| `winapp2.ini` | скачанная база правил winapp2, если вы её загружали |

---

## Права администратора

Приложение всегда запускается от администратора. Это нужно для очистки Standby
Memory через `ntdll!NtSetSystemInformation`. Завершение процессов текущего
пользователя тоже работает.

## Технические детали

- **WinAPI:** `CreateToolhelp32Snapshot`, `EnumWindows`, `GetExtendedTcpTable`,
  `OpenProcessToken`/`GetTokenInformation` (владелец процесса),
  `SendMessageTimeout(WM_CLOSE)`, `TerminateProcess` (через `Process.Kill`),
  `NtSetSystemInformation` (Standby Memory), `GlobalMemoryStatusEx`,
  `DwmSetWindowAttribute` (тёмный заголовок).
- **Обновления программ:** вызываются `winget.exe` и `choco.exe`. Вывод `winget upgrade`
  не имеет машинно-читаемого формата (только таблица), поэтому таблица разбирается по
  позициям начала колонок из строки заголовка и по их **порядку**, а не по названиям —
  так разбор работает и на локализованном winget.
- **Single-instance** — именованный `Mutex` (`Local\WindowsProcessCleaner.singleinstance`).
  Локальный TCP-порт **49876** используется только для того, чтобы попросить уже
  запущенный экземпляр показать окно; если порт занят, приложение всё равно запустится
  нормально.
- **Мониторинг** процессов идёт в фоновом потоке (не в UI), период настраивается
  (5..300 с, по умолчанию 15). Данные о процессах берутся напрямую через
  `OpenProcess` + `GetProcessTimes`/`GetProcessMemoryInfo`, а не через
  `Process.GetProcessById` — последний делает полный снимок системы на каждый вызов, и на
  600+ процессах один проход занимал десятки секунд.
- Поэтому «5 минут простоя» отсчитываются с момента, как приложение начало наблюдать за
  процессом, а не с его запуска.
- **Ключи командной строки:** `/tray` — стартовать свёрнутым, `/auto` — выполнить
  автоочистку процессов и выйти, `/analyze` — посчитать мусор на диске без удаления.
